# 正式配置与运行时状态

正式配置由分目录 YAML 保存：数据库连接及认证、账号密码哈希、平台逐库授权、表字段登记快照、人工说明、查询权限、Action 参数、脚本与 action-libraries/ 公共函数库、知识 description 与正文。当前 `revision` 与内容校验继续防止并发覆盖；不保存配置版本历史，不生成 `version/`、`state/`、模板或公共片段目录。

YAML 自有字段统一采用小驼峰，如 `maxRows`、`denyUnless`、`mcpEnabled` 和 `businessUserId`；动态业务标识、参数名、SQL 与脚本正文保留原值。SQLite 列名与 HTTP JSON 契约保持不变。

全局 `management.db` 只维护平台身份、全局认证和源目录。运行时不创建业务 SQLite、不创建 `CONFIG_RECORD`、`CONFIG_VERSION`、`QUERY_TOOL`、`QUERY_FRAGMENT`、`KNOWLEDGE_SEARCH` 或磁盘搜索索引。旧表定义只在测试迁移样本及标明历史用途的 SQL 文档中保留。

## 可重建数据

- 知识检索在内存中处理本次读取的正式 YAML 内容；`prompts/list` 和 `prompts/get` 读取同一份 description 和正文。权限检查每次使用当前账号和授权；旧知识关联限制仍按当前表策略过滤，普通保存保留，只有明确确认解除并保存后才取消。新建知识无需关联表。无缓存有效期延迟。
- 权限 SQL 的编译结果及绑定名列表只在请求内存中存在，保存时去除 `compiled_sql`、`compiled_deny_unless`、`params` 与 `deny_unless_params`。Action 自己的参数定义和 tagged SQL 不受此清理影响。
- API 与 MCP 的正式配置读取通过相同文件锁读取完整 YAML 世代，每次请求重读；单库配置、认证和知识读取仅加载目标库，知识检索复用本次读取的记录，不重复遍历全部数据库。全局配置编辑和数据库目录列表仍按需读取全部数据源。YAML 字段规范直接比较转换前后的字段映射，不再重新生成并解析 YAML。任一进程保存后，另一进程下一次读取立即可见。旧身份版本或被撤销的权限不能靠已有 MCP 会话继续使用。

动作使用标准静态 `import` / `export` 声明依赖，无 YAML uses 字段。运行时只装载可达模块，编译缓存按数据库与源码内容隔离，每次调用仍创建独立 JS 执行环境。库中的 SQL 与动作共享事务、权限改写和执行限制；库代码变化会使待确认预览失效。

## 结构扫描候选的生命周期

管理 API 的自动扫描和该 API 收到的手动扫描共用一个 Catalog 实例；管理 MCP 中发起的扫描属于 MCP 自己的 Catalog。每个实例对每个数据库只保留一个待确认候选及最后检查状态，最近变化报告最多保留 20 次。扫描、检查、查看候选不会写 YAML 或配置历史。

相同基线和相同结构的再次扫描保留候选 ID；新差异替换候选，无变化则清除候选。普通查看不消耗候选，不用过期计时器中断正常确认流程。其他配置编辑继续使用最新 revision，人工说明变化会重新计算差异。登记结构基线或连接变化会使旧候选失效。

确认必须交给生成候选的服务实例，并携带候选 ID 和当前 revision。服务端重新扫描真实结构，检查基线及配置并发变化，成功后才保存新的正式登记快照和保守调整的访问配置，随后清除候选。另一进程确认后，旧进程下次查看也会因基线变化隐藏旧候选。

重启、切换到另一实例或跨 API/MCP 查看不会恢复候选、检查时间及报告；已登记结构、人工说明和权限仍在。重新发起扫描即可继续查看和确认。自动扫描启动后会重建检查状态，失败保留最后正式快照；没有变化的检查不会提高配置 revision。

## 升级、回执与审计

公共 SQL 片段只由离线一次性迁移解析并递归展开到每张表的权限 SQL 和前置检查，`${userId}` 等身份与 SQL 绑定保持原文。缺失、循环及格式错误明确失败，不跳过权限、不发布不完整规则。旧命名查询不进入运行时，原内容留在升级备份中。旧扫描辅助记录、编译结果和历史版本不迁入新配置。对已经生成过早期 YAML 的环境，停服后再次执行 `go run ./cmd/migrate-state -data-dir data`：发现旧大写下划线字段或派生字段时备份原 YAML 及密钥，转换为小驼峰并清理派生字段，保持当前 revision；再次执行不重复备份。

Action 幂等登记、回执和确认令牌继续由 MCP 内存持有，API 通过私有 Unix socket 共享；重启清空，不进入 YAML、业务 SQLite 或审计回执表。工作台正式调用通过本人业务认证访问真实 MCP；确认后使用同一 request_id 并设置 result_only:true 查询回执。查询缺失回执返回 unknown，绝不重新登记或执行写入。普通审计独立异步写入 `audit.db`，失败不影响功能。

升级前一致性快照、原始旧库、独立 `audit.db` 都有各自职责，保留不删。YAML 的 `.next` / `.previous` 和全局提交日志仅用于中断恢复，完成提交后清理，不构成历史版本存储。

## 验证

`go test ./...` 覆盖迁移失败保护、SQL 绑定、Action 事务与内存回执、扫描候选查看/确认/重启流程。`TestDerivedStateProcessPeer` 使用真实第二个 OS 进程修改 YAML，验证现有 MCP 会话立即读到新知识和权限 SQL，并在身份停用后立即拒绝请求。`TestDiscoveryCandidateMemoryLifecycle` 验证扫描不改写 YAML、候选不能跨进程复用、重扫后可确认，正式结构更新对另一实例立即可见。
